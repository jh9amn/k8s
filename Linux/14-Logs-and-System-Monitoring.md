# 1. Introduction to Linux Logging

Logs are records of events generated by:

- Linux Kernel
- Applications
- Services
- System Processes
- Users

Logs help administrators understand what is happening inside the system.

Example:

```text
Application Started
↓

Log Generated

↓

Stored in /var/log

↓

Administrator Reads Logs
```

---

# Why are Logs Important?

Imagine a production web server suddenly stops working.

Without logs:

```
❌ No idea what happened
```

With logs:

```
Application Error
↓

Database Connection Failed
↓

Cause Found
↓

Issue Fixed
```

Logs save hours of debugging.

---

# 2. Linux Logging Architecture

Modern Linux uses two logging systems.

```
                Linux Kernel
                     │
                     ▼
             systemd-journald
                     │
         ┌───────────┴───────────┐
         ▼                       ▼
    journalctl             rsyslog (optional)
                                  │
                                  ▼
                           /var/log/*
```

---

# Components

| Component | Purpose |
|------------|----------|
| Kernel | Generates kernel logs |
| Applications | Generate application logs |
| journald | Collects logs |
| rsyslog | Stores and forwards logs |
| journalctl | Reads journal logs |

---

# 3. syslog

`syslog` is the traditional Linux logging standard.

It defines:

- Log format
- Log levels
- Log facilities

Many Linux distributions still support syslog-compatible logging.

---

## Syslog Workflow

```text
Application

↓

syslog()

↓

rsyslog

↓

/var/log/messages
```

---

# 4. rsyslog

`rsyslog` is an advanced implementation of syslog.

Features:

- High performance
- Remote logging
- Log filtering
- Log forwarding
- Database output

---

Ubuntu:

```bash

```

Restart:

```bash
sudo systemctl restart rsyslog
```

Enable:

```bash
sudo systemctl enable rsyslog
```

---

## Configuration Files

```text
/etc/rsyslog.conf

/etc/rsyslog.d/
```

# 5. systemd-journald

Modern Linux distributions use **systemd-journald**.

Instead of writing directly to text files, logs are first stored in the systemd journal.

Benefits:

- Structured logs
- Indexed storage
- Fast searching
- Boot-specific logs

---

## Check Status

```bash
systemctl status systemd-journald
```

# 8. Log Levels

Each log message has a severity.

| Level | Description |
|---------|-------------|
| Emergency | System unusable |
| Alert | Immediate action required |
| Critical | Critical failure |
| Error | Runtime error |
| Warning | Warning message |
| Notice | Normal but important |
| Info | General information |
| Debug | Debugging details |

# 9. System Monitoring

System monitoring is the process of continuously observing the health and performance of a Linux system.

A system administrator monitors:

- CPU Usage
- Memory Usage
- Disk Usage
- Running Processes
- Network Usage
- System Load
- Hardware Resources

Without monitoring, it becomes difficult to identify performance bottlenecks and troubleshoot issues.

---

# Monitoring Architecture

```text
                Linux System
                     │
      ┌──────────────┼──────────────┐
      ▼              ▼              ▼
   CPU Usage     Memory Usage    Disk Usage
      │              │              │
      └──────────────┼──────────────┘
                     ▼
           Monitoring Commands
                     │
     top • htop • free • vmstat • iostat
                     │
                     ▼
          System Administrator
```

# 11. The `top` Command

`top` is the most commonly used Linux monitoring tool.

It displays:

- CPU usage
- Memory usage
- Running processes
- Process IDs
- User information
- System load

Run:

```bash
top
```

Example:

```text
top - 12:40:52 up 3 days, 2 users

Tasks: 210 total

Cpu(s): 8.5% us

Mem: 8042 MB total
```

---

|---------|----------|

| SHR | Shared memory |
| %CPU | CPU usage |
| %MEM | Memory usage |
| TIME+ | CPU time |

## Interactive Keys

# 13. Memory Monitoring

Linux memory consists of:

```text
RAM
│
├── Used
├── Free
├── Cached
└── Buffers
```

Useful command:

```bash
free -h
```

Example:

```text
Mem:
Total: 8G

Used: 3G

Free: 2G

Cache: 3G
```

---

# Understanding Cache

Linux uses unused RAM as cache.

Example:

```text
8 GB RAM

3 GB Used

3 GB Cache

2 GB Free
```

The cache is automatically released when applications need memory.

Therefore:

> High memory usage is not always a problem.

# 32. Log Rotation

Log files continuously grow.

Without rotation:

```text
1 MB

↓

10 MB

↓

500 MB

↓

5 GB

↓

Disk Full
```

Linux uses **logrotate** to automatically manage log files.

---

# Why Log Rotation?

Benefits:

- Prevents disk from filling
- Compresses old logs
- Deletes old logs
- Improves performance
- Eases maintenance

---

# 33. logrotate

Check configuration:

```bash
cat /etc/logrotate.conf
```

Additional configurations:

```text
/etc/logrotate.d/
```

---

# Example Configuration

```text
/var/log/myapp.log {

    daily

    rotate 7

    compress

    missingok

    notifempty
}
```

Meaning:

- Rotate daily
- Keep 7 backups
- Compress old logs
- Ignore missing logs
- Don't rotate empty files

---

# Test Configuration

```bash
sudo logrotate -d /etc/logrotate.conf
```

Force rotation:

```bash
sudo logrotate -f /etc/logrotate.conf
```

# 35. Real-World Troubleshooting Scenarios

In production environments, system administrators and DevOps engineers rely on logs and monitoring tools to quickly identify and resolve issues.

---

## Scenario 1: High CPU Usage

### Symptoms

- Server becomes slow
- High response time
- Users report delays

### Investigation

Check CPU usage:

```bash
top
```

or

```bash
htop
```

Find the process consuming the CPU.

Example:

```text
PID    USER     %CPU
4521   nginx    95.4
```

Inspect the process:

```bash
ps -fp 4521
```

Check related logs:

```bash
journalctl -u nginx
```

Possible solutions:

- Restart the service
- Optimize the application
- Increase CPU resources
- Investigate infinite loops

---

## Scenario 2: Disk Full

Symptoms:

```text
No space left on device
```

Check filesystem usage:

```bash
df -h
```

Find large directories:

```bash
du -sh /*
```

Find large files:

```bash
find / -type f -size +500M
```

Possible solutions:

- Delete unnecessary logs
- Rotate logs
- Remove temporary files
- Extend storage

---

## Scenario 3: Memory Exhaustion

Check memory:

```bash
free -h
```

View memory usage:

```bash
top
```

Identify large processes.

Possible causes:

- Memory leaks
- Large applications
- Too many processes

---

## Scenario 4: SSH Login Failure

Check service:

```bash
systemctl status ssh
```

Read logs:

```bash
journalctl -u ssh
```

Ubuntu:

```bash
cat /var/log/auth.log
```

Possible causes:

- Wrong password
- Incorrect SSH key
- Firewall
- Disabled SSH service

---

## Scenario 5: Service Not Starting

Check status:

```bash
systemctl status nginx
```

Read logs:

```bash
journalctl -xe
```

Test configuration:

```bash
nginx -t
```

Restart:

```bash
systemctl restart nginx
```
